2. Function Calling 核心流程

这是整个程序的核心链路：LLM 根据 system_prompt 理解业务，按需生成 SQL 并调用 exc_sql。

sequenceDiagram actor U as 用户 participant UI as TUI / WebUI participant Bot as Assistant 门票助手 participant LLM as qwen-flash participant Tool as ExcSQLTool exc_sql participant DB as MySQL ubr U->>UI: 输入自然语言问题 UI->>Bot: messages 追加 user 消息 Bot->>LLM: system_prompt + 对话历史 + tools 定义 LLM-->>Bot: 返回 tool_call sql_input Bot->>Tool: call params JSON Note over Tool: 解析 sql_input
database 默认 ubr Tool->>DB: pd.read_sql 执行查询 DB-->>Tool: 查询结果 DataFrame Note over Tool: head 10 行
to_markdown 格式化 Tool-->>Bot: 返回 Markdown 表格或错误信息 Bot->>LLM: 将 tool 结果回传 LLM-->>Bot: 生成自然语言回答 Bot-->>UI: 流式输出 response UI-->>U: 展示分析结果

3. exc_sql 工具内部逻辑

flowchart TD Start([call 被调用]) --> Parse[json.loads 解析 params] Parse --> GetSQL[取 sql_input] Parse --> GetDB[取 database 默认 ubr] GetSQL --> Connect[create_engine 建立 MySQL 连接] GetDB --> Connect Connect --> Exec[pd.read_sql 执行 SQL] Exec -->|成功| Limit[df.head 10 取前10行] Limit --> Format[to_markdown 转 Markdown] Format --> ReturnOK([返回查询结果]) Exec -->|异常| ReturnErr([返回 SQL执行出错 信息])
属性值
工具名exc_sql
参数sql_input（必填，string）
可选参数database（默认 ubr）
连接池pool_size=10, max_overflow=20, connect_timeout=10
结果限制最多返回前 10 行，防止数据量过大
